## 二、已修复的问题（均为实测复现，非推测）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 背景发白、浅色主题下文字看不清 | `Paint.setColor` 会把上一帧淡出歌词的低 alpha 带进 `LinearGradient`；`setShader` 不会重置 alpha | 画渐变前显式 `setColor(0xFFFFFFFF)` 重置为不透明 |
| 2 | 歌词永远停在第 1 行，不滚动 | 滚动位置只在首次布局时初始化，之后没有逐帧缓动更新，`animLine` 从不前进 | 每帧 `animLine += (target - animLine) * 0.22`，首帧直接吸附到目标，误差 < 0.008 行即判定到位 |
| 3 | 同一句歌词显示两次 | 三个独立原因叠加：①播放器反复上报同一句被当成新句；②最后一句一直显示到曲终；③本机缓存时间轴与本次播放位置错位 | ①`lastText` 去重 + 同句出现位置差 ≤ 15 s 视为同一次；②末句且位置已越过它，不再记为新行；③同句出现在比记录早 45 s 以上的位置且已有 ≥3 行，判定"又从头放"，整条时间轴按这一遍重建 |
| 4 | 设置面板滚不动，后面的选项看不到 | `ScrollView` 在 `wrap_content` 高度下测量时按内容撑开，自己认为无需滚动 | 面板高度改为屏高的固定比例，`ScrollView` 拿到确定高度 |
| 5 | 切主题后设置面板直接消失 | 同一个点击回调里先 `dismiss()` 旧面板再 `show()` 新面板，新窗口被旧窗口的移除流程一起带走 | 改为 `post()` 到下一帧再 `show()`，并把主题切换做成面板内原地重绘 |
| 6 | 弹窗时状态栏露出黑边 | 沉浸标记之外系统栏仍按默认色绘制 | 补 `FLAG_FULLSCREEN` + 按主题色设置 `systemUiVisibility` 与状态栏/导航栏颜色 |

另外修掉的实现问题（无独立现象，属隐患）：

- **时间轴落盘不原子**：原先直接写目标文件，播放中进程被杀会留下半截文件。改为写 `.tmp` 再 `renameTo`，失败则删目标重试；读取时不足 3 行视为损坏直接丢弃，不会把半截时间轴当完整歌词显示。
- **缓存目录无上限**：长期使用会占满存储。`LyricCache` 增加 300 个文件的按修改时间淘汰，单文件写入上限 128 KB，单曲上限 600 行。
- **崩溃日志无限增长**：`CrashLog` 超过 256 KB 自动清理。
- **LRC 解析覆盖不全**：`STAMP` 正则统一支持 `[mm:ss]`、`[mm:ss.xx]`、`[mm:ss.xxx]` 与 `[mm:ss:xx]`，一行多时间戳（`[00:12.00][01:20.00]词`）逐个展开，并处理 `[offset:±ms]` 与 `[ti/ar/al/by:]` 标签；解析后统一排序。
- **封面读取无保护**：`MediaMetadata.getBitmap()` 遇到异常直接返回 `null`，界面退回占位封面，不崩。

## 四、端到端验证

写了一个临时"模拟播放器"APK，创建真实 `MediaSession` 并逐句推送媒体通知，走完整条链路：

```
媒体通知 → MediaAccessService 缓存 → MediaSession.Token → MediaController
        → 元数据（歌名/歌手/专辑/封面/时长）→ LyricStream 拼时间轴 → PlayerView 绘制
```

结果：第一遍逐句累积正确；退出重进后本机缓存直接给出完整时间轴；四套主题、沉浸歌词、空闲时钟、设置面板切换均正常。`docs/screenshots/` 下 8 张截图均取自该链路。

## 五、遗留风险（未修复，需真车确认）

1. **未在真车验证。** 模拟器没有真实蓝牙栈。若原厂界面有歌名而本应用读不到，说明该车机没把蓝牙媒体暴露为标准 `MediaSession`，只能靠厂商 SDK，非本应用可解。
2. **歌词依赖播放器上报。** 蓝牙 AVRCP 不传歌词；播放器不写 `DISPLAY_SUBTITLE` / 通知正文就没有歌词。本应用无网络权限，不会联网搜词。
3. 部分车机的媒体通知不带 `MediaSession.Token`，代码已退回 `MediaSessionManager.getActiveSessions()`；若厂商限制了该接口，仍会读不到。
4. APK 使用本地开发签名，覆盖安装旧版本需先卸载（会清设置与歌词缓存）。
